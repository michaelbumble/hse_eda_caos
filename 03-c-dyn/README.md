## Байты, адреса и указатели

Память можно представить как последовательность байтов. **У каждого байта есть свой адрес** - номер, по которому процессор обращается к этому байту.

```text
адрес:      0x1000  0x1001  0x1002  0x1003
            ┌─────┬─────┬─────┬─────┐
содержимое: │ ??  │ ??  │ ??  │ ??  │
            └─────┴─────┴─────┴─────┘
```

Объект может занимать несколько последовательных байтов. Например, если `sizeof(int) == 4`, один `int` занимает 4 байта. Адресом объекта считается адрес его первого байта.

```c
int x = 42;
int *p = &x;
```

Здесь `&x` - адрес объекта `x`, а `p` - переменная, которая хранит этот адрес. Операция `*p` обращается к объекту по сохранённому адресу. У самого указателя `p` тоже есть адрес: `&p`.

Для массива элементы лежат последовательно, без промежутков:

```c
int values[3];
```

Если `sizeof(int) == 4`, массив занимает 12 байтов:

```text
values
  │
  ▼
┌──────────┬──────────┬──────────┐
│ values[0]│ values[1]│ values[2]│  3 × 4 = 12 байтов
└──────────┴──────────┴──────────┘
```

Поэтому `&values[1]` на `sizeof(int)` байтов больше, чем `&values[0]`. При арифметике указателей `p + 1` означает «следующий объект того же типа», а не обязательно «следующий байт».

**Выравнивание.** У типа может быть требование, чтобы адрес его объекта был кратен определённому числу байтов. Например, 64-битный указатель обычно должен быть выровнен по 8 байтам: его адрес должен делиться на 8. Компилятор учитывает это при размещении объектов и может добавлять неиспользуемые байты (`padding`) между полями структуры и в её конце. Поэтому `sizeof(struct)` может быть больше суммы размеров полей. `malloc` возвращает память с выравниванием, подходящим для стандартных типов, а в задаче `allocator` размер блока нужно округлять вверх до кратности 8.

У многоразрядных значений порядок байтов внутри объекта зависит от платформы. На распространённых little-endian системах младший байт хранится по меньшему адресу. При обычной работе с переменными C это скрыто, но становится важно при чтении объекта как набора байтов и при разборе бинарных форматов.

## Виды памяти процесса

- **Стек** — хранит кадры вызовов функций: локальные переменные, аргументы и служебную информацию. При входе в функцию создаётся новый кадр, при выходе он перестаёт существовать. Размер локальных объектов должен быть известен при компиляции, а их время жизни ограничено функцией. Нельзя возвращать указатель на локальную переменную. Имеет ограниченный размер (обычно 1-8 МБ)
- **Статическая память** — хранит глобальные и статические переменные. Они существуют всё время работы программы. Глобальные переменные и статические переменные без явной инициализации заполняются нулями.
- **Динамическая память (куча)** — используется для объектов, размер и время жизни которых определяются во время выполнения, то есть неизвестны заранее. Память выделяется через `malloc`, `calloc` или `realloc` и освобождается через `free`. Доступ сохраняется после выхода из функции, пока память не освобождена. Так же используется для больших объектов, так как ее объем ограничен объему свободной оперативной памяти компьютера (гигабайты).
- **Машинный код** — инструкции функций находятся отдельно от данных, обычно в сегменте `.text`. При вызове функции её код не копируется на стек: на стеке создаётся только кадр вызова.

Упрощённая схема всей памяти процесса:

```text
┌──────────────────────┐
│ Машинный код (.text) │
├──────────────────────┤
│ Статические данные   │
├──────────────────────┤
│ Куча                 │
├──────────────────────┤
│ Стек                 │
└──────────────────────┘
```

Схема показывает логические области, а не гарантированное расположение адресов в конкретной ОС.

## Функции для работы с динамической памятью

Все эти функции объявлены в `<stdlib.h>`.

### `malloc`

```c
void *malloc(size_t size);
```

Выделяет не менее `size` байтов и возвращает адрес начала блока. Содержимое блока **не инициализировано**: там могут быть произвольные значения. При ошибке возвращается `NULL`.

```c
int *values = malloc(10 * sizeof(*values));
if (values == NULL) {
    // Обработать ошибку.
}
```

`sizeof(*values)` предпочтительнее `sizeof(int)`: при изменении типа элементов выражение не придётся исправлять.

### `calloc`

```c
void *calloc(size_t count, size_t size);
```

Выделяет память для `count` объектов размера `size` и заполняет все байты нулями. При ошибке возвращается `NULL`. В отличие от ручного вычисления `count * size`, `calloc` проверяет переполнение при умножении.

```c
int *values = calloc(10, sizeof(*values));
```

Для целочисленных массивов нулевые байты дают нулевые значения элементов.

### `realloc`

```c
void *realloc(void *ptr, size_t new_size);
```

Изменяет размер ранее выделенного блока. Может расширить его на месте или переместить в другой адрес. Старое содержимое сохраняется в пределах меньшего из старого и нового размеров; новые байты не инициализированы.

```c
int *new_values = realloc(values, 20 * sizeof(*values));
if (new_values == NULL) {
    // Старый values всё ещё действителен и должен быть освобождён.
} else {
    values = new_values;
}
```

Нельзя сразу писать `values = realloc(values, ...)`: при ошибке будет потерян единственный указатель на старый блок. После успешного `realloc` старым адресом пользоваться нельзя, даже если новый адрес совпал со старым.

### `free`

```c
void free(void *ptr);
```

Освобождает блок, полученный от `malloc`, `calloc` или `realloc`. После `free` указатель нельзя разыменовывать и передавать в `free` повторно. Вызов `free(NULL)` безопасен и ничего не делает.

## Free list

В задаче `allocator` нужно реализовать собственные функции выделения и освобождения памяти. Освобождённые с помощью `free` блоки памяти не возвращаются ОС, а сохраняются в **free list** — односвязном списке свободных блоков, чтобы их можно было использовать повторно.

```text
freelist
   │
   ▼
┌──────┬──────┐    ┌──────┬──────┐    ┌──────┬──────┐
│ size │ next │───►│ size │ next │───►│ size │ NULL │
└──────┴──────┘    └──────┴──────┘    └──────┴──────┘
```

Каждый блок начинается со служебного заголовка `Block`: поле `size` хранит размер доступной пользователю части, а `next` указывает на следующий свободный блок. Пользователю возвращается не адрес заголовка, а адрес на 8 байтов дальше — начало полезной области блока.

```text
адрес заголовка  адрес, который получает пользователь
       │         │
       ▼         ▼
┌──────────────┬─────────────────────────────────────────┐
│ size, next   │ полезная область                        │
└──────────────┴─────────────────────────────────────────┘
      Block                    size байтов
```

Работа аллокатора:

1. `alloc_mem(size)` ищет в `freelist` первый блок достаточного размера.
2. Если блок найден, он удаляется из списка и возвращается пользователю.
3. Если подходящего блока нет, аллокатор запрашивает у ОС новую память через `sbrk`. Размер округляется вверх до кратности 8 для выравнивания.
4. `free_mem(ptr)` добавляет освобождённый блок в начало `freelist`.

Пока блок выдан пользователю, его нет в `freelist`. Один и тот же блок нельзя одновременно считать выделенным и свободным, а освобождать его повторно нельзя.

## Что важно помнить

- После `malloc`, `calloc` и `realloc` нужно проверять результат на `NULL`.
- Память `malloc` не инициализирована, а `calloc` заполняет выделенные байты нулями.
- После `realloc` нужно использовать возвращённый указатель: старый адрес мог стать недействительным.
- Каждый успешно выделенный блок необходимо освободить ровно один раз через `free`.
- Для односвязного списка `head == NULL` обозначает пустой список, а `next == NULL` — последний узел.
- В задаче `allocator` свободные блоки хранятся в `freelist`; если подходящего блока нет, память запрашивается у ОС через `sbrk`.
